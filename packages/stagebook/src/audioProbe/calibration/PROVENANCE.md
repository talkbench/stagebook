# Calibration assets: provenance

The channel-order probe ([#663](https://github.com/talkbench/stagebook/issues/663)) ships the pipeline's own calibration assets, byte for byte. Each MP4 here has the sidecar the pipeline wrote for it; `calibrationAssets.test.ts` checks every MP4 against its sidecar's `hash` and `size_bytes`, and the embedded copies in `calibrationAssets.generated.ts` against the MP4s.

## Source

- Repository: `Talk-Lab/conversation-processing-pipeline` (private), branch `main`
- Path: `transforms/compose_group/calibration/`
- Generated by `compose_group` 3.0.0 at pipeline commit `8ff36c2f` (the sidecars' `direct_transform.git_sha`), and committed to `main` in `7fd33ee7` (2026-11-11), from #183 (merged as #509)
- Re-vendored and checked identical to `main`: 2026-11-13 (#839)

Each asset is one channel count, 2 to 8: a C-channel Opus track (mapping family 255) at 48 kbps per channel, the same arguments as a 3.0.0 group recording, in which source channel k is silent except for a 20 ms 1 kHz marker at 0.10 + 0.06·k s; then a stereo AAC track carrying a 3 kHz tone at −30 dBFS (amplitude 0.03125), both `default`. The schema-2 sidecars record the encoder arguments, the marker schedule and the tone. The 2-channel asset's bytes are unchanged from compose_group 2.0.0, because 2 × 48 kbps equals the old fixed 96 kbps.

## Re-vendoring

When the pipeline regenerates the assets (after any change to its `build_audio_output_args`), re-vendor them. From this directory (`packages/stagebook/src/audioProbe/calibration/`), run one command per file: the seven MP4s and their seven sidecars.

```bash
gh api "repos/Talk-Lab/conversation-processing-pipeline/contents/transforms/compose_group/calibration/calib_2ch.mp4?ref=main" -H "Accept: application/vnd.github.raw" > calib_2ch.mp4
gh api "repos/Talk-Lab/conversation-processing-pipeline/contents/transforms/compose_group/calibration/calib_2ch.mp4.sidecar.json?ref=main" -H "Accept: application/vnd.github.raw" > calib_2ch.mp4.sidecar.json
```

Then, from the repository root, regenerate the embedded copies. The script refuses to write if any MP4 doesn't match its sidecar's hash.

```bash
node packages/stagebook/scripts/embed-calibration-assets.mjs
```

Finally, rebuild the `sim_mixed_<C>ch.mp4` test fixtures, which are derived from these assets, with `packages/stagebook/public/audio-probe/generate.sh`; keep its encoder arguments in step with the pipeline's. Then rerun the unit tests and the component tests (`src/audioProbe/audioProbe.ct.tsx`).
