# Calibration assets: provenance

The channel-order probe ([#663](https://github.com/talkbench/stagebook/issues/663)) ships the pipeline's own calibration assets, byte for byte. Each MP4 here has the sidecar the pipeline wrote for it; `calibrationAssets.test.ts` checks every MP4 against its sidecar's `hash` and `size_bytes`, and the embedded copies in `calibrationAssets.generated.ts` against the MP4s.

## Source

- Repository: `Talk-Lab/conversation-processing-pipeline` (private)
- Pull request: #248, a draft, on branch `feature/183-dual-track-group-audio`
- Path: `transforms/compose_group/calibration/`
- Generated by `compose_group` 2.0.0 at pipeline commit `1faa70c` (the sidecars' `direct_transform.git_sha`), 2026-10-05
- Last checked identical to that branch: 2026-10-06, at its head `328b4aa`

Each asset is one channel count, 2 to 8: a C-channel Opus track (mapping family 255) in which source channel k is silent except for a 20 ms 1 kHz marker at 0.10 + 0.06·k s, then a stereo AAC track carrying a 3 kHz tone, both `default`. The sidecar records the encoder arguments and the marker schedule.

The sidecars record the AAC tone's amplitude as 0.25, but the tone in every asset peaks at −30 dBFS (about 0.032). The probe works at either level: WebKit, which plays the AAC track, still fails, and a browser that mixed the tone into the Opus channels would still keep them above the probe's floor for far longer than a marker.

## Re-vendoring

PR #248 is still a draft. If its assets change before it merges, re-vendor them. From this directory (`packages/stagebook/src/audioProbe/calibration/`), run one command per file: the seven MP4s and their seven sidecars.

```bash
gh api "repos/Talk-Lab/conversation-processing-pipeline/contents/transforms/compose_group/calibration/calib_2ch.mp4?ref=feature/183-dual-track-group-audio" -H "Accept: application/vnd.github.raw" > calib_2ch.mp4
gh api "repos/Talk-Lab/conversation-processing-pipeline/contents/transforms/compose_group/calibration/calib_2ch.mp4.sidecar.json?ref=feature/183-dual-track-group-audio" -H "Accept: application/vnd.github.raw" > calib_2ch.mp4.sidecar.json
```

Once the PR merges, use `ref=main`. Then, from the repository root, regenerate the embedded copies. The script refuses to write if any MP4 doesn't match its sidecar's hash.

```bash
node packages/stagebook/scripts/embed-calibration-assets.mjs
```

Finally, rebuild the `sim_mixed_<C>ch.mp4` test fixtures, which are derived from these assets, with `packages/stagebook/public/audio-probe/generate.sh`. Then rerun the unit tests and the component tests (`src/audioProbe/audioProbe.ct.tsx`).
